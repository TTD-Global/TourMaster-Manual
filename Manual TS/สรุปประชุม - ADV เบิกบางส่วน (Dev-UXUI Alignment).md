**ที่มา:** สรุปจากไฟล์ transcript ของการประชุม 2 ครั้ง (Job Order/Guide Only และ Advance/สรุปรายงาน) — เอกสารนี้ไม่ได้ถอดเสียงจากไฟล์ mp3 ใหม่ แต่รวบรวมจากไฟล์สรุปการประชุม (-Summary.md) ที่แนบมา

## 1. เป้าหมายหลัก: เปลี่ยน ADV ให้เบิกบางส่วนได้

เดิมระบบเบิกล่วงหน้า (Advanced Payment) น่าจะเบิกเป็นก้อนเดียว การประชุมนี้ปรับให้ **เบิกได้หลายรอบ (partial)** จากยอดที่ตั้งไว้ ประเด็นสำคัญ:

### สถานะของรายการเบิก
| สถานะ | ความหมาย |
|-------|----------|
| `Save` | บันทึกฉบับร่าง → ขึ้นสถานะ `In Progress` / `Draft` |
| `In Progress` | หลังเลือกรายการแล้วส่งไปหน้า InfoGate |
| `Complete` | เบิกเสร็จสมบูรณ์ แก้ไขตัวเลขไม่ได้อีก ต้องใช้ **Add Extra Advanced** ถ้าจะเบิกเพิ่ม |

**คำศัพท์/ปุ่มที่เสนอปรับ:** `Record Payment` → `Invocate`, `Record` → `InfoGates`, และพิจารณาใช้ `Save`/`Complete` แทน `Approved` เพื่อลดความสับสน — **ยังไม่ final ต้องตกลงคำศัพท์ให้ตรงกันทุกหน้า**

### ตรรกะยอดเงิน (real-time)
- ยอดใน `Pending` (รอเบิก) ต้องลดลงทันทีเมื่อมีการเบิกบางส่วน
- ยอดใน `Pending` หายไปเมื่อเบิกครบ
- ยอดใน `InfoGate` ต้องอัปเดตแบบเรียลไทม์เช่นกัน

### UX การเบิกเพิ่ม (Add Extra Advanced)
1. กด **Add Extra Advanced** → ระบบแสดงตารางให้เลือกรายการเบิกก่อน (ไม่ auto ไปหน้าถัดไป)
2. ต้องกด **InfoGates** เอง เพื่อไปหน้าถัดไป
3. เสนอ 2 ปุ่มทางเลือก: **Save** (อยู่หน้าเดิม แก้ไขต่อ) / **Complete** (ไปหน้าสรุป)
4. หน้า `Info Gate`: แสดงรายการที่เลือก + อนุญาตเพิ่ม/แก้ไขก่อนเปลี่ยนสถานะ — ต้องแยกให้ชัดระหว่าง "ยอดที่ระบบคำนวณ" กับ "ยอดที่ผู้ใช้เลือกจริง (Selected)"
5. หน้า `Complete`: แสดงจำนวนรอบเบิก (เช่น "เบิกครั้งที่ 1", "รอบที่ 2") + ยอดรวมทั้งหมดจากทุกรอบ
6. **แท็กนับรอบการเบิก** ต้องไม่หายเมื่อเปลี่ยนหน้า
7. เสนอเพิ่มสรุป Option/หน่วย/จำนวนคน ไว้ด้านบนหน้า Info เพื่อดูภาพรวมโดยไม่ต้องสลับหน้า

### ปัญหาที่พบ
- ข้อมูลตัวอย่างที่ให้ทีม Dev เป็นค่าคงที่ (คูณด้วย 20) ทำให้เข้าใจผิดเรื่องการคำนวณต้นทุน → **ต้องปรับ mock data ให้ตรงเคสจริงก่อนเริ่ม dev**
- ยังไม่มีกติกาชัดเจนว่าดึงรายการจาก `Pending` มาเบิกอย่างไร และกระทบสถานะเดิมแค่ไหน

## 2. การรวบยอด Advance ในหน้าสรุป Expense (จากประชุมที่ 2)

- เมื่อเบิกหลายรอบ (เช่น 10 คน + 5 คน + 5 คน) **ตกลงให้รวบเป็นยอดเดียว (15 คน)** ในหน้าสรุป Expense เพื่อให้คำนวณ Actual ง่ายขึ้น
- ยอดรวมทั้งจำนวนคนและจำนวนเงินจากทุกรอบที่เบิก
- **⚠️ คำถามเปิด (จากทีม อีควาย):** ถ้า Cost type เป็น `All` หรือ `Fix` ที่ค่าเงินคงที่ (ไม่ได้อิงจำนวนคน) จะคิด Adv. Cost ในหน้า Expense อย่างไร — ประเด็นนี้ไม่มีอยู่ใน transcript การประชุม

  **แนวทางที่เสนอ (วิเคราะห์จากโครงสร้างระบบปัจจุบัน — ยังไม่ใช่มติทีม ต้องยืนยันอีกครั้ง):**
  ระบบปัจจุบันคิด `Advance Cost = Cost(Unit) × Pax` ซึ่งตรงกับ Cost Type = **Person** เท่านั้น ส่วน **All** และ **Fix** ต้องแยก logic:
  - **All (เหมาจ่าย):** ราคาไม่ผูกกับจำนวนคน ถ้าคิดซ้ำทุกรอบที่เบิกบางส่วนจะเกิด double-charge → ควรคิดยอดนี้แค่ครั้งเดียวในรอบแรกที่เบิก รอบถัดไปให้ disable/gray-out ไม่ให้เพิ่มซ้ำ
  - **Fix (คิดตามช่วง Min–Max Pax):** tier ราคาต้องอิงจาก **pax สะสมทั้งหมด** ไม่ใช่ pax เฉพาะรอบนั้น เช่น รอบแรกเบิก 10 คน (tier 1–10 = 100), รอบสองเบิกเพิ่ม 5 คน รวมเป็น 15 คน (ข้ามไป tier 11–20 = 200) → ต้องคิดเฉพาะส่วนต่าง (delta = 200-100 = 100) ในรอบสอง ไม่ใช่คิดเต็ม 200 ซ้ำ — สอดคล้องกับที่ประชุมพูดถึงเรื่องต้องแยก "ยอดที่ระบบคำนวณ" กับ "ยอดที่ผู้ใช้เลือกจริง (Selected)" ไว้แล้วในข้อ 1
- ประเด็นเปิด: การรวบยอดอาจทำให้ตรวจสอบยอดแต่ละรอบยากขึ้น — มีการเสนอทำ "ลิงก์กลับไปดูรายละเอียด" ในแถบ Advance ที่ปิดงานแล้ว แต่ **ยังไม่สรุปว่าจะทำหรือไม่**
- ปัญหาข้อมูล "Person" ซ้ำหลายรายการในรายงาน (คาดว่าเกิดจากแยกตาม Booking แทนที่จะรวบเป็นรายการเดียว) — **ยังไม่มีข้อสรุปวิธีแก้**

### การปรับหน้าสรุปรายงาน (UI)
- ขยายขนาด/น้ำหนักตัวอักษรของยอดรวม (Total) ให้เด่นขึ้น
- จัด Layout ใหม่: ย้าย Language ขึ้นด้านบน, วาง Total Pack ใกล้กับ Option เพื่อเทียบง่าย
- ถ้าไม่มี Option ให้แสดงเป็น `-` ตามด้วยจำนวน (แต่ยังไม่ชัดเจนกรณี Language ไม่มีข้อมูล)

### ขั้นตอนอนุมัติ
- แก้ตามที่ตกลงแล้วส่งให้ **พี่วีน (ชื่นวีน)** อนุมัติ (UAT)
- **ตกลงจะไม่รับแก้ไขยิบย่อยเพิ่มเติมหลังจากนี้** (เช่น ปรับขนาดตัวอักษรเล็กน้อย) — เพื่อปิดรอบงานนี้

## 3. หัวข้ออื่นที่เกี่ยวข้อง (Job Order / Guide Only) — บริบทเสริม

เนื่องจากอยู่ในการประชุมเดียวกัน อาจกระทบ scope งาน จึงสรุปไว้เป็นบริบท:

- **Job Order:** เพิ่ม notification บนรายการที่ `Complete` แล้วแต่มีการแก้ไข (Guide/รถ/Booking) หมดอายุเองใน 3 ชม., เพิ่มสถานะสีส้มเมื่อ Trip Code เปลี่ยนจนต้องออก Job Order ใหม่, ย้าย Advanced Search ออกมาด้านนอก, เพิ่มแสดงผล Guide 2 ที่เคยตกหล่น
- **Booking List / Check-in List:** ใช้ Advanced Search เป็น logic หลัก, ปรับ UI ให้เหมาะกับ Notebook, เพิ่มค้นหาด้วย Trip Code/Booking Number, เพิ่มเรียงตามเวลาทริป, แยกสถานะ Pending (เหลือง)/Complete
- **Guide Only:** ปัญหาปัจจุบันคือระบบผูก "Guide Only" กับ Supplier ทำให้ Dashboard นับรถผิดพลาด → เสนอแยกกลุ่ม "Guide Only" ออกจาก Supplier โดยตรง และเพิ่ม option "No Guide" ใน dropdown สำหรับกรณีใช้รถแต่ไม่ใช้ไกด์

## 4. ประเด็นที่ยังไม่สรุป ต้องตัดสินใจเพิ่ม (Action ก่อนเริ่ม Dev/Design)

1. **นิยามคำศัพท์สถานะ/ปุ่ม** ให้ชัดและสอดคล้องกันทุกหน้า (Save, Complete, Approved, Invocate)
2. **กติกาการดึงรายการจาก Pending** เข้ามาเบิก และผลกระทบต่อสถานะเดิม
3. **วิธีจัดการ "Person" ซ้ำ** ในหน้าสรุป Expense — รวบเป็นรายการเดียว หรือปรับคำอธิบายแทน
4. **แนวทางแสดงผล Language ที่ไม่มีข้อมูล** ในหน้าสรุป (ตอนนี้มีแค่กรณี Option ไม่มีข้อมูล = `-`)
5. **UI แสดง Option ในหน้า Job Order** และขนาดตัวอักษรบนมือถือของ Check-in List — ยังไม่ final
6. **กรอบเวลาพัฒนา:** ประมาณ 2 สัปดาห์ (ยังต้องยืนยัน)
7. รอ [Speaker 2] ตรวจสอบผลกระทบทางเทคนิคของ Guide Only และยอด Extra/Extend ที่ค้างอยู่ พร้อมสอบถาม "แบงค์" เรื่อง requirement กรณีไกด์ต้องย้ายรถ
8. **การคิด Adv. Cost เมื่อ Cost type เป็น `All`/`Fix`** (ค่าเงินคงที่ ไม่อิงจำนวนคน) ในหน้า Expense — ยังไม่มีข้อสรุปจากทีม มีแนวทางที่เสนอไว้ในหัวข้อ 2 (คิด All ครั้งเดียว, คิด Fix จาก pax สะสม + delta) ต้องให้ทีมยืนยันก่อนเริ่ม dev ส่วนการรวบยอด
