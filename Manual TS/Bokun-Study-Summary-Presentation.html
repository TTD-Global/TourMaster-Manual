Bókun Study — สรุปให้ทีมฟังก่อนคุยกลยุทธ์

ผลจากการเข้าไปทดลองใช้จริงบน Bókun Trial Account และสำรวจ DMC System เพื่อเข้าใจว่า Bókun คือระบบอะไร ทำไมตลาดถึงต้องการ และเราจะแข่งขันอย่างไร

"เบื้องต้น ลองเข้าไปใช้ และศึกษาเกี่ยวกับเขา และนำมาสรุปให้ทีมฟังกันก่อนครับ" — Boss James

01 · ภาพรวมระบบ

Bókun คือระบบอะไร

Bókun เป็น SaaS Booking & Distribution Platform สำหรับธุรกิจทัวร์และกิจกรรม ก่อตั้งที่ไอซ์แลนด์ปี 2014 ผสม 3 อย่างเข้าด้วยกันในระบบเดียว:

Booking Engine

จองและจัดการ Availability/Pricing ของสินค้าทัวร์

Channel/Inventory Manager

ขายพร้อมกันหลายช่องทาง sync สต๊อกอัตโนมัติ

CRM + เครื่องมือขาย

เก็บข้อมูลลูกค้า, Promo code, ชำระเงินในตัว

จากการทดลองสร้างสินค้าจริง ("Bangkok Temple Walking Tour") พบเมนูหลัก: Bookings, Experiences, Sales tools, Your resellers, Marketplace, Operations, Reports, Settings — ออกแบบให้เริ่มจาก "สร้างสินค้า" แล้วเลือกช่องทางกระจายขาย

02 · ทำไมตลาดต้องการ

ทำไมบริษัททัวร์ถึงอยากใช้ Bókun

  • หาลูกค้าใหม่จากหลายช่องทางในระบบเดียว — Booking widget, OTA (Viator, GetYourGuide, Airbnb), Marketplace 2,000+ ราย
  • ไม่ต้องมีทีม IT พัฒนาระบบเอง — SaaS พร้อมใช้ เหมาะกับ Operator ขนาดเล็ก-กลาง
  • ลด Overbooking — Sync สต๊อกข้ามทุกช่องทางขายอัตโนมัติ
  • เครื่องมือขายครบ — Promo code, Commission group, Payment ในตัว, Referral link, AI ช่วยเขียนคำโฆษณา
  • เชื่อม Viator/TripAdvisor ลื่นไหลเป็นพิเศษ — เพราะเป็นเจ้าของเดียวกัน

สรุป: Bókun ตอบโจทย์ Operator ที่ "อยากขายได้มากขึ้น ผ่านช่องทางหลากหลายขึ้น โดยลงทุนน้อยที่สุด"

03 · ทำไม Tripadvisor ซื้อ

TripAdvisor เข้าซื้อ Bókun (20 เมษายน 2018)

เติมเต็มฝั่ง Supply ที่ TripAdvisor ขาด ไม่ใช่ขยายฐานลูกค้า

แก้ปัญหา Supply-side

TripAdvisor แข็งด้าน Demand อยู่แล้ว แต่ไม่มีเครื่องมือช่วย Operator จัดการสินค้า/สต๊อก/ราคา

ดึง Operator รายเล็กเข้าดิจิทัล

Operator จำนวนมากยังใช้มือ/สเปรดชีต Bókun ช่วยดึงสินค้าเข้าแพลตฟอร์มได้ง่ายขึ้น

ควบคุม Inventory เอง

ได้ Channel Manager ผูกตรงกับ Supplier แทนที่จะพึ่ง OTA อื่นเป็นตัวกลาง

04 · เทียบกับระบบเรา

Bókun vs DMC System — เหมือน/ต่างกันอย่างไร

DMC = B2B/Wholesale DMC ปิด · Bókun = B2B2C Distribution Platform เปิดกว้าง

โครงสร้างสินค้าExperience → Pricing categories + Availability rule + Auto FXProduct → Package → Unit แบ่งด้วย B2B/B2C flag

ต่างที่แก่น: Bókun = "ร้านค้าออนไลน์ + เครือข่ายกระจายสินค้า" เปิดกว้าง ส่วน DMC = "ระบบปฏิบัติการ B2B ปิด" ลึกกว่าด้านต้นทุน/สิทธิ์/KPI แต่ไม่มีชั้นขายตรงถึงผู้บริโภค
05 · คำถามสำคัญ

ถ้ารวม DMC + Tour System จะสู้ Bókun ได้ไหม?

คำตอบ: สู้ได้บางส่วน แบบมีเงื่อนไข — ไม่ใช่สู้ได้เต็มรูปแบบ

แข็งแรงกว่าจริง

ด้านปฏิบัติการ + ต้นทุน + ความสัมพันธ์ B2B

DMC (ควบคุมราคาส่ง/Agent-Supplier จริง) + Tour System (Grouping → รถ/ไกด์ → Job Order → Check-in → ปิดต้นทุน) ให้ความลึกที่ Bókun ไม่มี — Bókun มีแค่ Passenger list/Pick-up list ระดับพื้นฐาน ไม่มี Job Order เชิงลึก และไม่มี KPI พนักงานเลย

ยังสู้ไม่ได้

ด้านการหาลูกค้า + ขายตรงถึงผู้บริโภค + กระจายสินค้า

ทั้ง DMC และ Tour System ไม่มี Storefront, ไม่เชื่อม OTA รายใหญ่, ไม่มี Marketplace เปิด, ไม่มี CRM ผู้บริโภค, ไม่มีระบบรับชำระเงินออนไลน์ — การรวมสองระบบไม่ได้เติมเต็มช่องว่างนี้โดยอัตโนมัติ เพราะทั้งคู่ถูกออกแบบมาเป็นระบบภายใน (Internal/B2B) ไม่ใช่แพลตฟอร์มสาธารณะ

ข้อสรุปสำหรับที่ประชุม

DMC + Tour System ไม่ได้ถูกออกแบบมาแข่งกับ Bókun ในสนามเดียวกัน — เทียบ "หลังบ้านต่อหลังบ้าน" เราดีกว่าจริง แต่เทียบ "แพลตฟอร์มขายต่อแพลตฟอร์มขาย" เรายังไม่มีของชิ้นนั้นเลย

06 · แนวทางที่เป็นไปได้

ทางเลือกเชิงกลยุทธ์ (ให้ทีมถกกันต่อ)

  • ไม่แข่งตรง — วางตำแหน่ง DMC + Tour System เป็นเครื่องยนต์หลังบ้านที่แข็งแกร่งที่สุด รับสินค้า/Booking จาก Bókun หรือ OTA อื่นเข้ามาบริหารต่อ
  • สร้างชั้นขายเพิ่ม — ลงทุนพัฒนาชั้น B2C/Storefront/Payment ใหม่ต่อยอดจากระบบที่มีอยู่ เพื่อแข่งกับ Bókun โดยตรง (ใช้ทรัพยากร/เวลามาก)
  • ผสมทั้งสองแนวทาง — เปิดช่องทางขายเฉพาะกลุ่มเล็ก (เว็บ TTD เอง) โดยไม่แข่งเต็มรูปแบบกับ Marketplace ของ Bókun แต่ใช้จุดแข็งต้นทุน/ปฏิบัติการรักษาฐาน Agent เดิม
คำถามเปิดสำหรับทีม: ทำไมบริษัททัวร์ที่เป็นคู่ค้า Agent ของ TTD ถึงเลือกใช้ระบบเราต่อ แทนที่จะพึ่ง Bókun เอง? และมีความเป็นไปได้หรือไม่ที่จะ Integrate กับ Bókun/OTA เพื่อรับสินค้าเข้ามาบริหารต้นทุนในระบบเรา แทนที่จะสร้างช่องทางขายใหม่ทั้งหมด?
