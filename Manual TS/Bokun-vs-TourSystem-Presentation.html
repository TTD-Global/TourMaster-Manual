01 · ภาพรวม

ภาพรวมการสำรวจ

ทดลองสร้างบัญชี Bókun Start Trial จริง สร้าง Experience ทดสอบ ("Bangkok Temple Walking Tour") ตั้งค่า Availability, Pricing ครบ, ทดลอง Quick Book, และไล่ดูทุกเมนูหลัก: Bookings, Experiences, Sales tools, Your resellers, Marketplace, Operations, Reports, Settings โดยหลีกเลี่ยงขั้นตอนที่ต้องผูกบัตรเครดิตหรือชำระเงินจริงทั้งหมด

03 · สินค้า/โปรแกรม

Experience (Bókun) vs Program (Tour System)

Bókun — Wizard ขายสินค้า

ใช้ตัวช่วยแบบ wizard ทีละขั้น (Title → Description → Photos → Availability → Pricing) คล้าย "ตัวช่วยสร้างสินค้าขาย" มากกว่า "ตั้งค่าโปรแกรมทัวร์"

  • Generate with AI — ปุ่มให้ AI ช่วยเขียนคำโฆษณา/คำบรรยายสินค้า
  • Pricing categories หลายแบบ (Adults, Children, Infant, Senior, Youth) ตั้งเป็น Default ได้
  • Availability rule แบบ recurring (วันในสัปดาห์ + PAX ขั้นต่ำ-สูงสุด + สี rule)
  • Auto FX — แปลงสกุลเงินอัตโนมัติสำหรับขายข้ามประเทศ

Tour System — ควบคุมต้นทุน

เน้นความละเอียดด้านต้นทุนปฏิบัติการแทน ได้แก่ Itinerary, Cost, Allowance, Seller, Extra Cost, Guide Fee ซึ่ง Bókun ไม่มีแนวคิดนี้เลยในหน้าสร้างสินค้า เพราะ Bókun ใช้ THB เพียงสกุลเดียวและไม่มีชั้นควบคุมต้นทุนราคาต่อทริปแบบนี้

04 · การสร้าง Booking

2 เส้นทางของ Bókun vs ฟอร์มเดียวจบของ Tour System

Create Booking (Storefront)

จำลองหน้าเว็บขายจริงที่ลูกค้าจะเห็น เลือกวันที่ในปฏิทิน เลือกจำนวนคน คำนวณราคาสด

Quick Book (Staff-facing)

Wizard 5 ขั้นตอน: เลือกสินค้า → วันเวลา → จำนวนคน+ราคา → ข้อมูลลูกค้า (optional) → วิธีชำระเงิน (Pay now / Already paid / Pay later)

ข้อสังเกตจากการทดสอบจริง: ในขั้นตอน Quick Book ช่อง "Phone" ที่เป็น Optional เกิด validation error "Invalid phone number" ค้างอยู่แม้ปล่อยว่าง ทำให้กดยืนยัน Booking ไม่สำเร็จแม้เลือก "Pay later" แล้ว — เป็นจุดบกพร่อง (bug) ของ Bókun ที่พบระหว่างทดสอบจริง

Tour System ใช้ Create Booking แบบฟอร์มเดียวจบ ผูก Itinerary/Cost/Allowance ที่ตั้งไว้ล่วงหน้าจาก Program ทันที ไม่มีแนวคิด "ตะกร้าสินค้า" หรือ "ช่องทางชำระเงินลูกค้า" เพราะ Tour System ไม่ได้เก็บเงินจากนักท่องเที่ยวโดยตรง

05 · จุดต่างที่ใหญ่ที่สุด

ช่องทางขายและการกระจายสินค้า

ส่วนที่ Bókun มีแต่ Tour System ไม่มีเลย เพราะ Bókun ถูกออกแบบให้เป็นทั้งเครื่องมือขายและเครื่องมือปฏิบัติการในตัวเดียว

Booking Widgets

  • Button, Booking Calendar, Product page แปะลงเว็บไซต์ตัวเองได้ทันที

OTAs

  • เชื่อมต่อ Viator, GetYourGuide, Airbnb, booknordics, Civitatis, DayTrip4U ด้วยคลิกเดียว

Marketplace

  • เครือข่าย B2B กว่า 2,000 Operator/Reseller พร้อมระบบ Contract, Amendment, Proposal, Conversation

Booking Agents & Referral

  • Local agent จองแทนลูกค้าได้ในระบบ / สร้างลิงก์ติดตามคอมมิชชันสำหรับ Influencer

Tour System ไม่มีแนวคิด "ช่องทางขาย" เลย เพราะ Booking ถูกสร้างจากฝ่ายขาย/ระบบภายในอยู่แล้ว จึงเน้นบริหารสิ่งที่เกิดขึ้น "หลัง" ได้ Booking แทน

07 · รายงาน/การเงิน

มุมมองขาย vs มุมมองต้นทุน

หมวดBókunTour System
มุมมองหลักมองจาก "ช่องทางขาย" (Sales overview แยกตาม Channel, Income statement, Referral tracking พร้อมคอมมิชชัน)มองจาก "ต้นทุนปฏิบัติการ" (Advance, Expense, Balance, Cost Report แยกตามรถ/ไกด์/Supplier)
การคืนเงินEnhanced refund terms — ตั้งเงื่อนไขคืนเงินลูกค้าได้เองไม่มี เพราะไม่ได้รับชำระเงินจากลูกค้าโดยตรง
08 · ผู้ใช้งาน & สิทธิ์

User Roles, Connections และ Sales Settings

  • Bókun มี User Roles สำเร็จรูป 6 แบบ (Admin, Driver/Guide, Product manager, Sales, Sales manager, Technical) — ใกล้เคียงกับ Roles/Permissions ของ Tour System
  • Bókun มี Connections (API keys, Webhooks) เปิดให้ Developer เชื่อมระบบภายนอกเอง — Tour System ไม่มีชั้นนี้ให้ผู้ใช้ทั่วไปเข้าถึง
  • Bókun มี Sales settings ครบชุด (Payment providers: Stripe/PayPal/RePayD, Promo codes, Commission groups, Terms & Conditions) เพราะต้องรับเงินจากลูกค้าโดยตรง
  • หน้า Password & authentication ของ Bókun เป็น self-service เต็มรูปแบบ รองรับ Google SSO ส่วน Tour System ยังเป็นแค่ popup Reset Password ที่ Admin กดให้
09 · สรุป

จุดแข็ง-จุดต่างที่สำคัญที่สุด

Bókun แข็งเรื่อง "หาลูกค้า/ขาย"

  • ช่องทางกระจายสินค้าครบวงจร (Widget, OTA, Marketplace, Agent, Referral)
  • CRM ลูกค้า, Promo code, ระบบชำระเงินในตัว, AI ช่วยเขียนคำโฆษณา
  • เหมาะกับธุรกิจที่ต้องการหาลูกค้าใหม่ผ่านช่องทางออนไลน์หลากหลาย

Tour System แข็งเรื่อง "ควบคุมงานหลังบ้าน"

  • ผูก Booking เข้ากับกลุ่ม รถ ไกด์ Job Order และต้นทุนจริงในระบบเดียวอย่างละเอียดกว่ามาก
  • แยกเงินทดรอง/ค่าใช้จ่ายจริง/ยอดชดเชยเป็นขั้นตอนบัญชีเฉพาะ ซึ่ง Bókun ไม่มีแนวคิดนี้
  • เหมาะกับองค์กรที่ Booking เข้ามาจากฝ่ายขายอยู่แล้ว ต้องการควบคุมต้นทุนรายทริปละเอียด
สรุปสั้นๆ: Bókun ตอบโจทย์ "ก่อนขาย" และ "ระหว่างขาย" ได้ดีมาก แต่รายละเอียด "หลังขาย" (ปฏิบัติการหน้างาน + ปิดต้นทุน) ตื้นกว่า Tour System ชัดเจน ส่วน Tour System ตรงข้ามกัน คือแทบไม่มีชั้น "ขาย" เลย แต่ลึกมากในชั้น "ปฏิบัติการและต้นทุน" — ทั้งสองระบบจึงเสริมกันได้มากกว่าจะแข่งกันโดยตรง
10 · ข้อควรทราบ

ข้อควรทราบจากการทดสอบ

  • สร้างสินค้าทดสอบ "Bangkok Temple Walking Tour" (#1250611) ไว้ในบัญชี Bókun Trial เพื่อปลดล็อกฟีเจอร์สำรวจ — ยังคง Active อยู่ในระบบ ถ้าต้องการให้ปิด/ลบแจ้งได้
  • ไม่ได้ผูกบัตรเครดิต ไม่ได้เชื่อมต่อ Payment provider ไม่ได้ส่ง Contract ใน Marketplace จริง และไม่มีการชำระเงินใดๆ เกิดขึ้นระหว่างการทดสอบ
  • พบ bug ในขั้นตอน Quick Book ที่ validation ช่อง Phone (Optional) ค้าง Error แม้ปล่อยว่าง ทำให้ไม่สามารถกดยืนยัน Booking แบบ Pay later ให้จบขั้นตอนได้ในการทดสอบนี้
