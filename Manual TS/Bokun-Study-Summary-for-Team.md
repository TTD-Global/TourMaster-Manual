# สรุปศึกษา Bókun เพื่อเตรียมพรีเซนต์ทีม

*ตามที่ Boss James มอบหมาย: "เบื้องต้น ลองเข้าไปใช้ และศึกษาเกี่ยวกับเขา และนำมาสรุปให้ทีมฟังกันก่อนครับ"*

---

## 1. Bókun คือระบบอะไร

Bókun เป็น **SaaS Booking & Distribution Platform** สำหรับธุรกิจทัวร์และกิจกรรม (Tours & Activities) ก่อตั้งที่ไอซ์แลนด์ในปี 2014 โดยเป็นระบบที่ผสม 3 อย่างเข้าด้วยกันในตัวเดียว:

1. **Booking Engine** — ระบบจองและจัดการ Availability/Pricing ของสินค้าทัวร์
2. **Channel/Inventory Manager** — เชื่อมสินค้าเดียวไปขายได้พร้อมกันหลายช่องทาง (เว็บตัวเอง, OTA, Reseller) โดย sync สต๊อกอัตโนมัติไม่ให้ Overbook
3. **CRM + เครื่องมือขาย** — เก็บข้อมูลลูกค้า, Promo code, ระบบชำระเงินออนไลน์ในตัว

จากการเข้าไปทดลองใช้จริงด้วยบัญชี Trial (สร้างสินค้าทดสอบ "Bangkok Temple Walking Tour" ตั้งค่า Availability/Pricing และทดลอง Quick Book) พบว่าโครงสร้างเมนูหลักคือ Bookings, Experiences, Sales tools, Your resellers, Marketplace, Operations, Reports, Settings — ออกแบบมาให้ผู้ประกอบการเริ่มจาก "สร้างสินค้า" แล้วเลือกว่าจะกระจายขายไปช่องทางไหนบ้าง

## 2. ทำไมบริษัททัวร์ถึงอยากใช้ Bókun

- **หาลูกค้าใหม่ได้จากหลายช่องทางในระบบเดียว** — ไม่ต้องพัฒนาเว็บขายเอง สามารถแปะ Booking widget ลงเว็บไซต์ตัวเอง, เชื่อม OTA ใหญ่ (Viator, GetYourGuide, Airbnb) และเข้าถึง Marketplace ที่มี Operator/Reseller กว่า 2,000 รายทั่วโลกได้ทันทีด้วยคลิกเดียว
- **ไม่ต้องมีทีม IT พัฒนาระบบเอง** — เป็น SaaS พร้อมใช้ สมัครแล้วเริ่มขายได้ในไม่กี่วัน เหมาะกับ Operator ขนาดเล็ก-กลางที่ไม่มีงบสร้างระบบ
- **ลดปัญหา Overbooking** — Sync สต๊อก/คิวว่างข้ามทุกช่องทางขายอัตโนมัติ
- **มีเครื่องมือขายครบ** — Promo code, Commission group, ระบบรับชำระเงินในตัว (Stripe/PayPal), Referral link สำหรับ Influencer, และฟีเจอร์ Generate with AI ช่วยเขียนคำโฆษณาสินค้า
- **มาตรฐานอุตสาหกรรมที่ OTA รายใหญ่คุ้นเคย** — เพราะ Bókun เป็นของ TripAdvisor ทำให้เชื่อมกับ Viator/TripAdvisor ได้ลื่นไหลเป็นพิเศษ

พูดสั้นๆ คือ Bókun ตอบโจทย์ Operator ที่ "อยากขายได้มากขึ้น ผ่านช่องทางที่หลากหลายขึ้น โดยลงทุนน้อยที่สุด"

## 3. ทำไม TripAdvisor ถึงซื้อ Bókun

TripAdvisor ประกาศเข้าซื้อ Bókun เมื่อ **20 เมษายน 2018** (Bókun ก่อตั้งที่ไอซ์แลนด์ตั้งแต่ปี 2014) โดยเหตุผลหลักคือ:

- **แก้ปัญหา "Supply-side"** — ก่อนหน้านี้ TripAdvisor แข็งแรงมากด้าน Demand (นักท่องเที่ยวเข้ามาดูรีวิว/ค้นหาทัวร์บนแพลตฟอร์ม) แต่ไม่มีเครื่องมือช่วยผู้ประกอบการ (Supply) จัดการสินค้า/สต๊อก/ราคาให้พร้อมขาย การซื้อ Bókun ทำให้ TripAdvisor ได้ Booking engine + Channel manager มาเสริมฝั่ง Supply ทันที
- **ดึง Operator รายเล็กเข้าระบบดิจิทัล** — ผู้ประกอบการทัวร์จำนวนมาก (ตั้งแต่ธุรกิจท้องถิ่นขนาดเล็กไปจนถึงบริษัทระดับ Fortune 500) ยังจัดการ Booking ด้วยมือ/สเปรดชีต Bókun ช่วยให้ TripAdvisor เข้าถึงและดึงสินค้าจาก Operator เหล่านี้เข้ามาขายบนแพลตฟอร์มของตัวเองได้ง่ายขึ้น
- **ควบคุม Inventory/Availability แบบ real-time ได้เอง** — แทนที่จะพึ่งพา OTA อื่นเป็นตัวกลาง TripAdvisor ได้เทคโนโลยี Channel Manager ที่ผูกตรงกับ Supplier

กล่าวได้ว่า TripAdvisor ซื้อ Bókun ไม่ใช่เพื่อขยายฐานลูกค้านักท่องเที่ยว (ซึ่งมีอยู่แล้วมหาศาล) แต่เพื่อ "เติมเต็มขาที่ขาด" คือเทคโนโลยีฝั่ง Supply/Operator ให้ครบวงจร

## 4. Bókun vs DMC System (uat-dmc.ttdthailand.com) — เหมือน/ต่างกันอย่างไร

จากการเข้าไปสำรวจ DMC System จริง (Booking, Products, Special Offer, Agent, Supplier, User, Performance Evaluation) พบว่า DMC เป็นระบบแนวทาง **B2B/Wholesale DMC (Destination Management Company)** ในขณะที่ Bókun เป็น **B2B2C Distribution Platform** — แนวคิดหลักต่างกันตั้งแต่รากฐาน

| หมวด | Bókun | DMC System (TTD) |
|---|---|---|
| **กลุ่มลูกค้าเป้าหมาย** | ทั้ง B2C (ขายตรงนักท่องเที่ยวผ่านเว็บ/OTA) และ B2B (Reseller/Agent ผ่าน Marketplace) | B2B ล้วน — ทุก Booking ผูกกับ "Agent" เสมอ (มีช่อง Agent บังคับในฟอร์ม Create Booking) ไม่มีหน้าขายตรงถึงนักท่องเที่ยว |
| **โครงสร้างสินค้า** | Experience → Pricing categories (Adults/Children/Infant) + Availability rule รายสัปดาห์ + Auto FX ข้ามสกุลเงิน | Product (Activities/Transport) → Package → Unit (Adult/Child) แบ่งด้วย B2B/B2C flag และ Booking Type (เช่น "24 Hours Confirmation") ต่อสินค้า |
| **การสร้าง Booking** | 2 เส้นทาง: Storefront (ลูกค้าจองเอง) และ Quick Book (staff จองแทน) พร้อมตัวเลือกชำระเงิน Pay now/Already paid/Pay later | ฟอร์มเดียว "Create Booking" ระบุ Agent + Booking Type + Product/Package + Lead Person เสมอ ไม่มีแนวคิด "ตะกร้าสินค้า" หรือชำระเงินปลายทาง เพราะไม่ใช่การขายตรงผู้บริโภค |
| **ช่องทางกระจายสินค้า** | มี Booking widgets, เชื่อม OTA (Viator/GetYourGuide/Airbnb), Marketplace 2,000+ ราย, Referral link | ไม่มีช่องทางขายสาธารณะ — สินค้าเห็นเฉพาะ Agent ที่ผูกไว้ในระบบ (Manual/Automated Booking ID ต่อ Agent) |
| **การจัดการ Agent/Supplier** | Marketplace แบบเปิด จับคู่ Operator-Reseller ใหม่ได้เรื่อยๆ ผ่านระบบ Contract/Proposal | มี Agent List (16 ราย ในข้อมูลจริง) และ Supplier List (230 ราย) จัดการเฉพาะคู่ค้าที่ทำสัญญากับ TTD โดยตรง ไม่ใช่ Marketplace เปิดสาธารณะ |
| **Special Offer/ราคา** | Promo code, Commission groups ต่อช่องทางขาย | มีเมนู Special Offer แยก B2B และ Cost โดยเฉพาะ — เน้นบริหารต้นทุน/ราคาขายส่งต่อ Agent มากกว่าโปรโมชันแบบผู้บริโภค |
| **CRM ลูกค้าปลายทาง** | มี Customers module เก็บประวัติ/อีเมลนักท่องเที่ยวทุกคนที่เคยจอง | ไม่มี — เก็บเฉพาะข้อมูล Agent/Supplier ที่เป็นคู่ค้า ไม่เก็บข้อมูลนักท่องเที่ยวปลายทางโดยตรง |
| **ผู้ใช้งานภายใน** | User Roles สำเร็จรูป 6 แบบ (Admin, Driver/Guide, Product manager, Sales, Sales manager, Technical) | Role ชัดเจนแบบ Enterprise: Admin, Manager, Accounting, BD, CS & RSVN, MD พร้อมตาราง Permission แยกสิทธิ์เข้าถึงแต่ละเมนู (มีในคู่มือระบบ User Manual ของ DMC เอง) — สะท้อนโครงสร้างองค์กรจริงมากกว่า |
| **KPI/วัดผลพนักงาน** | ไม่มีแนวคิดนี้ — วัดผลจาก Sales overview ตามช่องทางขาย | มีโมดูล **Performance Evaluation (KPI)** แยก OP และ BD วัดผลงานพนักงานรายคน (Create Booking, Reserve Action) ต่อช่วงเวลา พร้อม Export — Bókun ไม่มีฟีเจอร์นี้เลย |
| **การสื่อสารกับคู่ค้า** | ผ่าน Conversation ในระบบ Marketplace | มีโมดูล **Email** แยกเฉพาะ (Send Email, Email History, Email Setting) ผูกกับ Booking/Agent โดยตรง |

### สรุปเหมือน/ต่าง

**เหมือนกัน:** ทั้งคู่มีแนวคิด "สินค้า (Product) → Package/Availability → Booking → Operations" คล้ายกันในระดับโครงสร้างข้อมูล และทั้งคู่ต้องจัดการ Supplier/ต้นทุนเบื้องหลัง

**ต่างกันที่แก่น:** Bókun ถูกออกแบบให้เป็น "ร้านค้าออนไลน์ + เครือข่ายกระจายสินค้า" เปิดกว้างสู่สาธารณะและนักท่องเที่ยวทั่วไป ส่วน DMC ถูกออกแบบให้เป็น "ระบบปฏิบัติการ B2B ปิด" สำหรับบริหารความสัมพันธ์กับ Agent/Supplier ที่มีสัญญาแล้วเท่านั้น — DMC จึงลึกกว่าในเรื่องการควบคุมต้นทุน สิทธิ์การเข้าถึงตามตำแหน่งงาน และการวัดผล KPI พนักงาน แต่ไม่มีชั้น "ขายตรงถึงผู้บริโภค" หรือ "หาคู่ค้าใหม่แบบเปิดกว้าง" แบบที่ Bókun มี

## 6. จุดเริ่มต้นสำหรับทีมช่วยกันคิดต่อยอด (ไม่ใช่ข้อสรุปสุดท้าย)

ตามที่ Boss James ระบุว่า "ให้ทีมสรุปความคิดว่าแนวทางที่เราจะเข้าไปแข่งขันกับ Bókun มีอะไรบ้าง" ส่วนนี้เป็นเพียง**ข้อมูลตั้งต้น**ให้ทีมต่อยอดในที่ประชุม ไม่ใช่บทสรุปที่ปิดประเด็นแล้ว:

**จุดแข็งเบื้องต้นของ DMC/ระบบเรา:**
- ควบคุมต้นทุนและความสัมพันธ์คู่ค้า (Agent/Supplier) ได้ละเอียดกว่า เหมาะกับโมเดล B2B ที่ TTD ดำเนินธุรกิจอยู่จริง
- มีระบบวัดผลพนักงาน (KPI) และสิทธิ์การเข้าถึงตามตำแหน่งงานที่ตรงกับโครงสร้างองค์กรจริง
- เป็นระบบที่ TTD ควบคุมเอง 100% ปรับแต่ง Workflow ให้ตรงกับกระบวนการภายในได้ไม่จำกัด (Bókun ต้องปรับตามสิ่งที่แพลตฟอร์มรองรับเท่านั้น)

**จุดอ่อนเบื้องต้นที่ควรถกกันต่อ:**
- ไม่มีช่องทางขายตรงถึงผู้บริโภคหรือเครือข่าย Marketplace แบบเปิด — ถ้าต้องการขยายฐานลูกค้าใหม่แบบ Bókun จะต้องพัฒนาเพิ่มเติมมาก
- ไม่มี CRM นักท่องเที่ยวปลายทาง จึงยากต่อการทำ Remarketing หรือสร้างความสัมพันธ์ระยะยาวกับผู้บริโภคโดยตรง
- ไม่มีระบบชำระเงินออนไลน์ในตัว/Promo code สาธารณะ

**คำถามเปิดสำหรับทีมช่วยกันตอบในที่ประชุม:**
- ทำไมบริษัททัวร์ (โดยเฉพาะที่เป็นคู่ค้า Agent ของ TTD) ถึงเลือกใช้ระบบเราต่อ แทนที่จะไปพึ่ง Bókun เอง?
- เราควรแข่งกับ Bókun ตรงๆ ในเชิง Distribution หรือควรวางตำแหน่งเป็น "หลังบ้านที่แข็งแกร่งกว่า" แล้วปล่อยให้ Bókun/OTA อื่นทำหน้าที่หาลูกค้าแทน?
- มีความเป็นไปได้หรือไม่ที่จะเชื่อมต่อ (Integrate) กับ Bókun/OTA เพื่อรับสินค้าเข้ามาบริหารต้นทุนในระบบเรา แทนที่จะสร้างช่องทางขายเองใหม่ทั้งหมด?

## 7. ถ้ารวม DMC + Tour System เข้าด้วยกัน จะสู้กับ Bókun ได้ไหม

คำถามนี้สำคัญเพราะ TTD มีอยู่แล้ว **2 ระบบที่ครอบคลุมกันคนละส่วน**: DMC (จัดหาสินค้า/บริหาร Agent-Supplier/ควบคุมต้นทุนขายส่ง) และ Tour System (ปฏิบัติการหน้างานเชิงลึก — Booking → Grouping → Vehicle/Guide → Job Order → Check-in → ปิดต้นทุนจริง) คำตอบคือ **"สู้ได้บางส่วน แบบมีเงื่อนไข"** ไม่ใช่ "สู้ได้เต็มรูปแบบ" เพราะจุดที่ทั้งสองระบบรวมกันแล้วแข็งแรง กับจุดที่ยังขาด เป็นคนละเรื่องกันชัดเจน

### สิ่งที่ DMC + Tour System รวมกันแล้ว "แข็งแรงกว่า Bókun จริง"

| ความสามารถ | DMC + Tour System (รวมกัน) | Bókun |
|---|---|---|
| ควบคุมต้นทุนและราคาขายส่งต่อ Agent | DMC มี Special Offer (B2B/Cost) จัดการราคาส่งเฉพาะคู่ค้า 16 Agent / 230 Supplier จริง | ไม่มีแนวคิด "ราคาส่ง" แบบ B2B ลึกขนาดนี้ เน้นราคาขายปลีกต่อผู้บริโภค |
| ปฏิบัติการหน้างานเชิงลึก | Tour System ผูก Booking → Grouping → รถ/ไกด์ → Job Order → Check-in → ปิดต้นทุนจริงในระบบเดียว | มีแค่ Passenger list + Pick-up list ระดับพื้นฐาน ไม่มี Job Order/Grouping เชิงลึก |
| วัดผลพนักงานภายใน (KPI) | DMC มี Performance Evaluation (OP/BD) วัด Create Booking/Reserve Action รายคน | ไม่มีฟีเจอร์นี้เลย |
| โครงสร้างสิทธิ์ตามตำแหน่งงานจริง | DMC มี Role แบบ Enterprise (Admin/Manager/Accounting/BD/CS&RSVN/MD) ตรงกับองค์กร TTD | มี Role สำเร็จรูป 6 แบบ ทั่วไป ไม่ผูกกับโครงสร้างองค์กรจริง |
| ความสัมพันธ์ Agent/Supplier ที่มีสัญญาแล้ว | DMC มีฐาน Agent/Supplier จริงจำนวนมากอยู่แล้ว (230 Supplier) | ต้องเริ่มสร้างใหม่ผ่าน Marketplace |

**สรุป:** ถ้าวัดกันที่ "ความลึกของฝั่งปฏิบัติการ + การควบคุมต้นทุน + การบริหารคู่ค้า B2B ที่มีอยู่จริง" DMC + Tour System เหนือกว่า Bókun อย่างชัดเจน เพราะ Bókun แทบไม่มีความลึกระดับนี้เลย — Bókun ตื้นกว่ามากในทุกจุดข้างต้น

### สิ่งที่ DMC + Tour System รวมกันแล้ว "ยังสู้ Bókun ไม่ได้"

| ความสามารถ | DMC + Tour System | Bókun |
|---|---|---|
| ช่องทางขายตรงถึงผู้บริโภค (B2C) | ไม่มีเลยทั้งสองระบบ | มี Storefront/Booking widget ครบ |
| เชื่อมต่อ OTA รายใหญ่ (Viator, GetYourGuide, Airbnb) | ไม่มี | มีในคลิกเดียว |
| Marketplace หาคู่ค้าใหม่แบบเปิดกว้าง | ไม่มี — ต้องทำสัญญาเองทีละราย | มี Marketplace เปิด 2,000+ ราย |
| CRM นักท่องเที่ยวปลายทาง | ไม่มี | มี Customers module เก็บประวัติ/อีเมล |
| ระบบรับชำระเงินออนไลน์จากผู้บริโภค | ไม่มี | มี Payment provider ในตัว (Stripe/PayPal) |
| Promo code / Referral สำหรับผู้บริโภคทั่วไป | ไม่มี | มีครบ |

**สรุป:** ในมุม "หาลูกค้าใหม่ + ขายตรงถึงผู้บริโภค + กระจายสินค้าออกสู่ตลาดโลก" DMC + Tour System รวมกันก็ยังมีช่องว่างเท่ากับตอนแยกกัน เพราะทั้งสองระบบถูกออกแบบมาให้เป็นระบบภายใน (Internal/B2B) ไม่ใช่แพลตฟอร์มสาธารณะ การนำมารวมกันไม่ได้เติมเต็มส่วนนี้โดยอัตโนมัติ

### ข้อสรุปสำหรับที่ประชุม

DMC + Tour System **ไม่ได้ถูกออกแบบมาแข่งกับ Bókun ในสนามเดียวกัน** — ถ้าเทียบกันแบบ "หลังบ้านต่อหลังบ้าน" (Operations + Cost control + B2B relationship) เรามีของที่ดีกว่าอยู่แล้วจริง แต่ถ้าเทียบกันแบบ "แพลตฟอร์มขายต่อแพลตฟอร์มขาย" (Distribution + B2C + Marketplace) เรายังไม่มีของชิ้นนั้นเลยไม่ว่าจะรวมสองระบบหรือไม่ ดังนั้นทางเลือกเชิงกลยุทธ์ที่เป็นไปได้ (ให้ทีมถกกันต่อ) คือ:

1. **ไม่แข่งตรง** — วางตำแหน่ง DMC + Tour System เป็น "เครื่องยนต์หลังบ้านที่แข็งแกร่งที่สุดในตลาด" แล้วรับสินค้า/Booking จาก Bókun หรือ OTA อื่นเข้ามาบริหารต่อ (ใช้จุดแข็งด้านปฏิบัติการเป็นตัวชูโรง แทนที่จะแข่งด้าน Distribution)
2. **สร้างชั้นขายเพิ่ม** — ลงทุนพัฒนาชั้น B2C/Storefront/Payment ใหม่ต่อยอดจาก DMC + Tour System ที่มีอยู่ เพื่อแข่งกับ Bókun โดยตรง แต่ต้องใช้ทรัพยากรและเวลาอีกมาก
3. **ผสมทั้งสองแนวทาง** — เปิดช่องทางขายเฉพาะกลุ่มเล็กๆ (เช่น เว็บของ TTD เอง) โดยไม่ต้องแข่งเต็มรูปแบบกับ Marketplace ของ Bókun แต่ใช้จุดแข็งด้านต้นทุน/ปฏิบัติการเป็นตัวรักษาฐาน Agent เดิมไว้
